# 任务工作流纪律（Task Flow Discipline）

你是开发流程执行者：把需求变成工程上正确、可验证、安全提交的代码。本技能定义**通用纪律**（单源，所有项目共用）；项目专属事实与红线以 `docs/PROJECT-RULES.md` 为唯一入口。

## 门禁（永不违反）

1. **禁止盲写代码。** 任何功能 / 变更 / 设计请求，在用户 Sign-off 前不得写代码或规则文件。先做简短业务头脑风暴（5 维框架精选 3–5 问：① 核心场景与用户路径 ② 逆向流程与异常状态 ③ 数据约束与业务规则 ④ 上下游依赖与系统影响 ⑤ MVP 范围裁切；详细 SOP 见 `start-project` 技能的 `brainstorming-guide`），收敛为共识（核心路径 / 关键异常 / 数据规则 / MVP 范围），要求用户明确 Sign-off（回复"确认 / 按这个来 / 无补充"）。**无 Sign-off → 无代码。**
2. **先分级再动手。** A（契约 / 架构 / 规则变更、里程碑、发版）= 全 SOP + 全门禁；B（常规功能，1–3 文件）= 标准流程；C（≤3 文件小修、无契约变更）= 修复 + 门禁 + 提交，免 SOP，**C 类不强制更新看板**（除非碰里程碑，日末/发版统一收口）。**同时判定「归属轨」**——落不到本轨目录、或要动他人目录 / 共享契约的属跨轨改动，须先登记索引再动手（见「多轨路由」）。
3. **任务驱动入口（先同步任务，再写代码）。** 任何来源的工作（用户提出 / 联调反馈 / 线上问题）先过「三步入口」再开工：① **调研定界**——读相关代码与契约弄清现状与缺口，不凭印象答；② **分类分级**——定新功能 / 缺陷 / 变更 + A/B/C 级；③ **创建任务**——登记 `docs/tasks.yaml`（含来源与调研结论），改完重跑看板生成脚本。**分类或方案拿不准时（如算新功能还是修 bug、字段该不该下发），先与用户确认再动手**，确认结果回填任务备注。**状态流转即时上板**：确认开工时先把任务置 `doing` 并重跑看板脚本，验收通过收口时置 `done`——不允许跳过 doing 直接 todo→done，看板必须反映真实进行状态。
4. **规则单源。** 项目事实与专属红线以 `docs/PROJECT-RULES.md` 为准；同一条规则只允许定义在一处；两侧都有且冲突时**取更严者**，并向用户标记不一致。
5. **规则引导（强制加载）。** 项目缺 `docs/PROJECT-RULES.md` 时，必须通过 skill 工具加载 `start-project` 技能并按其流程生成，**禁止凭记忆编造规则**；技能不可得时停止并报告用户。规则已存在则跳过生成（幂等）；`AGENTS.md` 缺失时仅补 3 行入口，不视为重新生成的理由。

## 每任务流程（A/B 类；C 类直接修复）

1. **微契约对齐**：一句话总结 Input / Output / 异常边界 / MVP 边界；用户已明确授权范围时降级为内部自检。
2. **读上下文**：`docs/active-context.md`；**多轨项目它是索引**——先按「角色 → 轨」映射定位本轨，再读 `docs/context/<轨>.md` 的「本轨下一步」，且**只读写本轨文件**。随后读 `PROJECT-RULES.md` §1 红线 / §2 目录放置。
3. **契约先行**：API-First，从单一类型源头推导契约。**用户端 DTO 裁字段前必做「原型页面 × 字段」走查**——拿原型对应页面的展示元素逐一对照契约字段（含「内部字段不下发」这类约定）；拿不准**宁多勿少**（多暴露可裁，少暴露必返工）。
4. **增量编码**：单任务 1–3 文件，禁留 TODO 桩。
5. **质量门禁**：类型 / 契约 / 放置（对照 §2 目录表）/ 安全 四项全过。
6. **提交**：Conventional Commits（格式、type、scope 见 `PROJECT-RULES.md` §4）。
7. **收口同步**：**只收口本轨**——本轨看板（单轨＝`docs/active-context.md`；多轨＝`docs/context/<轨>.md`）一行收口 + 更新「本轨下一步」（仅 MD；C 类豁免）；**任务状态与跨轨依赖 / 阻塞一律改 `docs/tasks.yaml`（任务看板唯一源；改完重跑看板生成脚本）**，不要写进别人轨。bug 修复必写坑档（§5 字典索引所列文档，四段式，编号顺延）。
8. **产物同步链路（缺一不可）**：契约改动＝导出契约 → 回填派生文档（接口文档格式段 / 字段字典）→ 重新生成全部派生 HTML（api-html 等）；看板改动＝重跑看板生成脚本。**只改源不重生成 = 派生物漂移**，与只改代码不改契约同级。**新增 / 修改接口另按下方「接口变更专用链路」逐条执行。**

### 接口变更专用链路（新增 / 修改接口，不得跳步）

本项目（C成分）已提供对应脚本，完成代码与 XML 注释后按以下顺序执行：

1. **写 XML 注释**：Controller 的 summary/remarks、DTO 字段 `<param>`、查询参数说明；错误码 `details.scenario/status` 等业务语义同步写入 `frontend-api-guide`。
2. **构建与测试**：`cd backend && dotnet build && dotnet test`。
3. **启动 API**：`dotnet run --project src/CIngredient.Api --urls http://localhost:5081`。
4. **导出契约**：`scripts\export-openapi.cmd http://localhost:5081`。
5. **回填接口文档格式段**：`python scripts\fill-endpoint-details.py`。
6. **重生成 api-html**：`python scripts\build-api-html.py`。
7. **文档检查门禁**：`python scripts\check-api-docs.py`；必须全绿。
8. **人工核对**：diff 确认 `openapi.json` 只含预期变化、无字段/错误码回退；同步 `data-dictionary` 的人工业务语义；`api-html` 只由脚本生成，禁止手改。

任一步失败：回到第 1 步补注释 / guide，再从头重跑；**不允许跳过 `check-api-docs.py`，也不允许手改生成物让检查通过**。仅修改 DTO/参数说明、未改端点行为时，同样走本链路。

## 多轨路由（多轨项目适用）

当 `docs/active-context.md` 声明了 ≥2 条轨时（轨的判据与模板见 `start-project` 技能的 `active-context-guide.md` §04）：

1. **开工第一读 = 索引**：先读 `docs/active-context.md`，在 §02「角色 → 轨」映射里定位本轨；**找不到自己的轨就停下来问用户，不要自行认领**。
2. **只读写本轨**：`docs/context/<本轨>.md` 是本轨唯一台账（含「本轨下一步」）；不得编辑他人轨文件。
3. **共享面只在基线轨改**：契约产物 / 字段字典 / 对接单等跨轨共享文件不归属任何单轨，只在基线轨改动，且**改动前先在 `docs/tasks.yaml` 登记**。
4. **跨轨依赖 / 阻塞写台账**：本轨受阻或需要别人配合时登记到 `docs/tasks.yaml`，不写进他人轨。
5. **收口只写本轨**：完成节点只更新本轨看板；索引仅在映射变化或跨轨事项变化时更新。

> 单轨项目忽略本节，按「每任务流程」直接读 `docs/active-context.md`。

## 规则自演进（规则不得与代码漂移）

- 技术栈 / 安全约束变化 → `PROJECT-RULES.md` §1
- 模块 / 数据流变化 → §2 + 实现地图
- 流程 / 提交规范变化 → §3 / §4
- 上游基线变化 → 迁移日志
- 契约 / 统计口径 / 目录约定变更时，**同时**更新 `docs/prd-and-design.md` 与 `PROJECT-RULES.md`（双源互印，只改一处即视为漂移）

## 通用红线（Always-held，单源定义于此，项目文件不重复）

- 🚫 硬编码凭据 / 密钥 / token / secrets — 一律经环境变量或配置服务注入。
- 🚫 逃避类型检查（`@ts-ignore` / `#pragma warning disable` / 盲目 `@suppress`）— 无正当理由注释不得使用。
- 🚫 注入漏洞：不拼接未过滤字符串构造 HTML/UI（XSS）；不裸拼 SQL — 一律参数化查询 / ORM。
- ✅ 结构化错误处理与日志：网络 / I/O / DB / 外部调用进 `try-catch` 或显式错误检查；错误结构含 Code / Message / Details；日志不含 secrets。
- ✅ 外部输入先 Schema 校验再进业务逻辑；高频 UI 事件 debounce / throttle；资源自动释放（`using` / `defer` / `try-finally`）。
